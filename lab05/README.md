*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,

x = 1/3

**Ответ:**

Математически результат выражения (x + y) - y всегда равен x = 1/3.

Но в компьютере числа типа float имеют ограниченную точность.

При увеличении y маленькое число x начинает терять значащие разряды во время сложения.

В double используется 53 значащих двоичных разряда.

Расстояние между соседними числами вычисляется по формуле:

2^(p-52), где p — двоичный порядок числа.

Максимальная погрешность округления равна 2^(p-53).

Например:

При y = 1:

p = 0, погрешность не больше 2^-53, то есть примерно 1.11 * 10^-16.

При y = 1000000:

p = 19, погрешность не больше 2^-34, то есть примерно 5.82 * 10^-11.

При y = 1000000000000:

p = 39, погрешность не больше 2^-14, то есть примерно 0.000061.

При y = 1000000000000000:

p = 49, шаг между числами равен 0.125.

Поэтому вместо 1/3 после сложения и вычитания получается 0.375.

При y = 10000000000000000:

p = 53, шаг между соседними числами равен 2.

Число 1/3 слишком маленькое и при сложении полностью теряется.

Поэтому результат становится равным 0.

Чем больше y, тем сильнее погрешность.

### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните ответ. Что произойдет, если тип* **double** *заменить на* **long double**?

```cpp
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```

**Ответ:**

В типе double максимальный порядок конечного нормализованного числа равен 1023.

Поэтому 2^1023 ещё можно представить, а 2^1024 уже выходит за допустимый диапазон.

Минимальное значение n = 1024.

При этом программа выведет inf.

Если заменить double на long double, диапазон чисел может стать больше.

Например, в 80-битном long double можно представить степени двойки до 2^16383.

Но в исходной программе pow(2, n) возвращает double, поэтому простая замена типа переменной не решит проблему.

Нужно написать:

```cpp
#include <iostream>
#include <cmath>

int main() {
    int n = 1024;

    long double s = pow(2.0L, n);

    std::cout << std::fixed << s << std::endl;
}
```

Для 80-битного long double бесконечность появится при n = 16384.

### Задание 9 **(2)**

*Напишите программу для решения следующей задачи.*

*Даны четыре рациональных числа. (Рациональное число - это число вида*
$\frac{p}{q}$, *где* $p$ *и* $q$ - *целые числа.) Напишите программу, которая сравнит сумму двух первых чисел с суммой двух последних чисел. Программа должна выводить* $1$, $0$ *или* $-1$ *в зависимости от результатов сравнения. Решение можно проверить в проверяющей системе*
[http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102](http://olymp3.isu.ru/cgi-bin/new-client?contest_id=102), *задача 03*.

**Ответ:**

Чтобы избежать погрешности вещественных чисел, будем сравнивать дроби с помощью целочисленной арифметики.

Обозначим четыре дроби как a/b, c/d, e/f и g/h.

Сравнивать нужно суммы:

a/b + c/d и e/f + g/h.

После приведения к общему знаменателю сравниваем числители.

Программа на C++:

```cpp
#include <iostream>
using namespace std;

int main() {
    long long a, b, c, d, e, f, g, h;
    cin >> a >> b >> c >> d >> e >> f >> g >> h;

    if (b == 0 || d == 0 || f == 0 || h == 0)
        return 0;

    if (b < 0) { a = -a; b = -b; }
    if (d < 0) { c = -c; d = -d; }
    if (f < 0) { e = -e; f = -f; }
    if (h < 0) { g = -g; h = -h; }

    __int128 left =
        ((__int128)a * d + (__int128)c * b) * f * h;

    __int128 right =
        ((__int128)e * h + (__int128)g * f) * b * d;

    if (left > right)
        cout << 1;
    else if (left < right)
        cout << -1;
    else
        cout << 0;

    return 0;
}
```

Если первая сумма больше, программа выводит 1, если меньше — -1, если суммы равны — 0.

### Задание 3 **(5)**

*Задано вещественное число в десятичной записи. Напишите программу для нахождения первых 1000 разрядов этого числа в двоичной записи.*

**Ответ:**

Для этой задачи нельзя использовать обычный double, потому что он хранит только 53 значащих двоичных разряда.

Поэтому будем работать с десятичной записью числа как со строкой.

Целую часть переведём обычным способом, а дробную будем последовательно умножать на 2.

Программа на Python:

```python
s = input().strip()

negative = s.startswith("-")

if negative or s.startswith("+"):
    s = s[1:]

if "." in s:
    whole, frac = s.split(".", 1)
else:
    whole, frac = s, ""

if whole == "":
    whole = "0"

integer = int(whole)

binary_integer = bin(integer)[2:]

numerator = int(frac) if frac else 0
denominator = 10 ** len(frac)

binary_fraction = ""

for i in range(1000):
    numerator *= 2

    if numerator >= denominator:
        binary_fraction += "1"
        numerator -= denominator
    else:
        binary_fraction += "0"

result = binary_integer + "." + binary_fraction

if negative and (integer != 0 or numerator != 0):
    result = "-" + result

print(result)
```

Получаем 0.101₂.

### Задание 4 **(3)**

*Изучая чужой код, программист обнаружил такую функцию.*

```cpp
long double acos_e(long double x, long double ep){
  if (x > 1+ep || x < -1-ep)
    return 0.0 / 0.0;
  else if (x>1)
    x=1;
  else if (x<-1)
    x=-1;
  return acos(x);
}
```

*Чем отличается эта функция от обычной функции арккосинуса? В чем смысл дополнительных проверок?*

Обычная функция acos определена только для чисел от -1 до 1.

Например, вместо 1 может получиться 1.0000000001.

Обычная функция acos в таком случае вернёт NaN.

Функция acos_e учитывает допустимую погрешность ep.

Если число выходит за пределы [-1-ep; 1+ep], функция возвращает NaN.

Если число немного больше 1, оно заменяется на 1.

Если число немного меньше -1, оно заменяется на -1.

После этого вызывается обычная функция acos.

Таким образом, дополнительные проверки нужны для защиты от небольших погрешностей вычислений.

### Задание 5 **(5)**

*Заданы координаты точек* $A$, $B$, $C$ *на плоскости. Координаты являются вещественными числами в диапазоне* $[0;10)$
*и содержат не более 6 знаков после точки. Используя формулу векторного произведения, напишите программу для определения расположения* $C$ *относительно вектора* $AB$ *(слева, справа, на прямой).*

*От вас требуется обосновать выбор значения* **eps** *при сравнении.*

**Ответ:**

Для определения расположения точки C относительно вектора AB используется векторное произведение:

D = (bx - ax) * (cy - ay) - (by - ay) * (cx - ax).

Если D > 0, точка C находится слева.

Если D < 0, точка C находится справа.

Если D = 0, точки лежат на одной прямой.

Так как координаты содержат не более 6 знаков после точки, их можно умножить на 1000000 и хранить как целые числа.

Это позволит избежать погрешности double.

Программа на C++:

```cpp
#include <iostream>
#include <string>
using namespace std;

long long read_coord() {
    string s;
    cin >> s;

    size_t pos = s.find('.');

    string whole = s.substr(0, pos);
    string frac = "";

    if (pos != string::npos)
        frac = s.substr(pos + 1);

    while (frac.size() < 6)
        frac += '0';

    return stoll(whole) * 1000000LL + stoll(frac);
}

int main() {
    long long ax = read_coord();
    long long ay = read_coord();
    long long bx = read_coord();
    long long by = read_coord();
    long long cx = read_coord();
    long long cy = read_coord();

    long long D =
        (bx - ax) * (cy - ay) -
        (by - ay) * (cx - ax);

    if (D > 0)
        cout << "left";
    else if (D < 0)
        cout << "right";
    else
        cout << "on line";

    return 0;
}
```

Обоснование eps:

Все координаты после умножения на 1000000 становятся целыми числами.

Вычисления выполняются точно, поэтому можно использовать eps = 0.

При этом переполнения long long не будет, поскольку координаты меньше 10, а произведения разностей после масштабирования по модулю меньше 10^14.

Таким образом, программа определяет расположение точки без ошибок округления.
