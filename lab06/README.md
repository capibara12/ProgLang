**Ответ:**

Я проверил четыре варианта объявления Pi. Для этого использовал следующую программу, меняя строку объявления Pi.


Первый вариант:

```cpp
const auto Pi = std::acos(0) * 2;
```

```cpp
constexpr auto Pi = std::acos(0) * 2;
```

```cpp
constexpr auto Pi = std::acos(x) * 2;
```

Программа не компилируется, так как x является обычной переменной и её значение нельзя использовать в таком константном выражении.

В лекции сказано, что для объявления констант времени компиляции используется constexpr. Значение такой константы должно быть известно на этапе трансляции.

### Задание 6 **(2)**

*Рассмотрим следующий фрагмент программы. Эта программа 1000000 раз обменивает значения двух длинных строк с использованием третьей строки. Проверьте, насколько быстро она работает.*

```cpp
std::string a(100000, 'a');
std::string b(100000, 'b');
for (int i=0;i<1000000;i++) {
   std::string c(a);
   a = b;
   b = c;
}
std::cout << a[0] << b[0];
```

*Попробуйте использовать для обмена значений строк функцию* **swap**. *Проверьте, изменилось ли время работы. В чем ошибка исходной программы? Исправьте исходную программу, чтобы ускорить ее работу. Изменения не должны затрагивать общий вид программы (присваивания, использование временной переменной).*

**Ответ:**

Сначала я рассмотрел исходную программу.

```cpp
#include <iostream>
#include <string>
#include <chrono>

int main() {
    std::string a(100000, 'a');
    std::string b(100000, 'b');

    auto start = std::chrono::steady_clock::now();

    for (int i = 0; i < 1000000; i++) {
        std::string c(a);
        a = b;
        b = c;
    }

    auto end = std::chrono::steady_clock::now();

    std::cout << a[0] << b[0] << std::endl;
    std::cout << std::chrono::duration<double>(end - start).count();

    return 0;
}
```

Для измерения времени я использовал chrono.

В исходной программе строки постоянно копируются. При каждом обмене создаётся копия строки длиной 100000 символов.

Из-за этого программа работает медленно.

Затем я использовал swap.

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <chrono>

int main() {
    std::string a(100000, 'a');
    std::string b(100000, 'b');

    auto start = std::chrono::steady_clock::now();

    for (int i = 0; i < 1000000; i++) {
        std::swap(a, b);
    }

    auto end = std::chrono::steady_clock::now();

    std::cout << a[0] << b[0] << std::endl;
    std::cout << std::chrono::duration<double>(end - start).count();

    return 0;
}
```

Функция swap меняет строки местами без копирования всех символов, поэтому работает быстрее.

Но по условию нужно исправить исходную программу, сохранив временную переменную и присваивания.

Для этого я использовал std::move.

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <chrono>

int main() {
    std::string a(100000, 'a');
    std::string b(100000, 'b');

    auto start = std::chrono::steady_clock::now();

    for (int i = 0; i < 1000000; i++) {
        std::string c(std::move(a));
        a = std::move(b);
        b = std::move(c);
    }

    auto end = std::chrono::steady_clock::now();

    std::cout << a[0] << b[0] << std::endl;
    std::cout << std::chrono::duration<double>(end - start).count();

    return 0;
}
```

В этой программе сохраняется общий вид исходного решения, но вместо копирования используется перемещение строк.

При проверке на GCC 14.2 с оптимизацией O2 получились следующие результаты:

Обычное копирование — примерно 6.33 секунды.

swap — примерно 0.0037 секунды.

std::move — примерно 0.0080 секунды.

На другом компьютере время может отличаться.

Во всех трёх случаях выводятся символы:

```text
ab
```

Так как обмен выполняется чётное количество раз, строки возвращаются в исходное положение.

Ошибка исходной программы заключалась в лишнем копировании больших строк.

В лекции сказано, что перемещение работает быстрее копирования, потому что не нужно создавать полные копии данных.

```python
n = 1

```

Функция globals() возвращает словарь глобальных переменных программы.

С помощью записи:

```python
globals()[name] = n
```

я создаю переменную с нужным именем и присваиваю ей значение.

После каждого присваивания n увеличивается на 1.

**Ответ:**

Я написал функцию, которая перебирает глобальные переменные и складывает значения типа int.

```python
def sumint():
    s = 0

    for name, value in globals().items():
        if type(value) == int:
            s += value

    return s
```

Пример использования в IDLE:

```python
>>> a = 10
>>> b = 1.5
>>> c = 15
>>> d = "hello"
>>> sumint()
25
```

Функция globals() возвращает словарь глобальных переменных.

Метод items() позволяет получить имя и значение каждой переменной.

С помощью:

```python
type(value) == int
```

я проверяю, относится ли значение к целочисленному типу int.

Если относится, добавляю его к сумме s.

Переменные типа float, str и других типов не учитываются.

В конце функция возвращает полученную сумму.

Функция работает с глобальными переменными среды IDLE. Если там уже есть другие целочисленные переменные, они тоже попадут в сумму.

Для проверки расположения переменных я написал несколько программ.

**1. Адреса переменных разных типов**

```cpp
#include <iostream>
#include <cstdint>

int main() {
    int a = 10;
    double b = 2.5;
    char c = 'A';
    long long d = 100;

    std::cout << "int: "
              << reinterpret_cast<std::uintptr_t>(&a)
              << " size: " << sizeof(a) << std::endl;

    std::cout << "double: "
              << reinterpret_cast<std::uintptr_t>(&b)

    std::cout << "char: "
              << reinterpret_cast<std::uintptr_t>(&c)

    std::cout << "long long: "
              << reinterpret_cast<std::uintptr_t>(&d)
              << " size: " << sizeof(d) << std::endl;

}
```

В программе создаются переменные четырёх разных типов.

Оператор & позволяет получить адрес переменной.

sizeof показывает её размер в байтах.

На распространённых компьютерах размеры обычно такие:

int — 4 байта.

double — 8 байт.

char — 1 байт.

long long — 8 байт.

Адреса могут отличаться не только на размер переменной, потому что компилятор может оставлять промежутки между ними для правильного размещения в памяти.

Проверять программу можно с разными уровнями оптимизации:

```bash
g++ -O0 main.cpp -o main0
g++ -O2 main.cpp -o main2
```

Здесь -O0 отключает оптимизацию, а -O2 включает оптимизацию.

Расположение переменных может отличаться, так как компилятор по-разному организует память.

**2. Переменные в разных блоках**

```cpp
#include <iostream>

int main() {

    {

```

Здесь переменные a и b находятся в разных блоках.

После выхода из первого блока переменная a перестаёт существовать.

Затем создаётся переменная b.

Так как время жизни переменных не пересекается, компилятор может использовать для них один и тот же участок памяти.

Поэтому адреса могут совпадать.

Но совпадение не гарантируется и зависит от компилятора и настроек оптимизации.

**3. Строки различной длины**

```cpp
#include <iostream>
#include <string>

int main() {
    std::string a = "Hello";
    std::string b(100, 'b');
    std::string c(10000, 'c');

    std::cout << "a: " << sizeof(a)
              << " address: " << &a << std::endl;

    std::cout << "b: " << sizeof(b)
              << " address: " << &b << std::endl;

    std::cout << "c: " << sizeof(c)
              << " address: " << &c << std::endl;

    std::cout << "b after change: "
              << sizeof(b)
              << " address: " << &b << std::endl;

}
```

Я создал три строки разной длины.

Первая содержит 5 символов, вторая 100, третья 10000.

Функция sizeof для всех трёх объектов std::string возвращает одинаковый размер в пределах одной реализации.

Это происходит потому, что sizeof показывает размер самого объекта string, а не количество символов внутри него.

Длинные строки обычно хранят символы в отдельной области памяти.

При изменении длины строки адрес самого объекта std::string остаётся прежним.

Но адрес внутреннего массива символов может измениться, если потребуется выделить больше памяти.

Для проверки внутреннего массива можно использовать:

```cpp
std::cout << static_cast<const void*>(b.data()) << std::endl;
```

По результатам этих примеров можно сделать вывод, что размещение переменных в памяти зависит от их типа, области видимости и работы компилятора.

Размер объекта std::string не зависит напрямую от длины содержащегося в нём текста.

Адреса и расстояния между переменными могут отличаться при разных запусках и уровнях оптимизации.
